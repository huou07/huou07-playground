## Findings supported by source

- web/app.py (1143 lines) combines metrics, service/process/VPN queries, app registry,
  icon fetching, DSH launch link and private relay servers. The HTTP handler
  subclasses stdlib HTTPServer; privileged control and file APIs are not present.
- GET /api/files returns Cockpit availability, not a NAS filesystem listing.
  Files UI links to Cockpit Files and the companion move page. Storage currently
  renders storage telemetry/devices; the proposed integrated browser is new work.
- POST /api/apps checks same-origin and body bounds. This is not independent
  owner authentication and must not be reused as authorization for NAS/policy.
  No exploit test or live exposure claim was made.
- Existing installed dashboard unit declares a separate account, NoNewPrivileges,
  ProtectHome and ProtectSystem. It does not establish current running state or
  isolate arbitrary agents-worker processes. No unit was changed or invoked.
- app.js pauses metrics/VPN timers when hidden, but its operations interval remains
  active and batches service/process/Cockpit/files/apps requests every 15 seconds.
  Metrics refresh uses setInterval without an in-flight guard. Slow responses can
  overlap. These are source-backed optimization candidates, not measured savings.
- Existing CSS provides green dark/light tokens, compact cards/sidebar, responsive
  layouts, focus indication and reduced-motion support. Preserve these assets.
- Existing CI runs make check only. A Playwright navigation/preferences/app flow
  exists but is not in that workflow. Rust manifests and project AGENTS were absent.
- Historical docs describe owner-account apps and earlier live-host tests. They are
  retained as archival references; the new initiative requires isolated workers
  and CI-only execution. No current deployment is inferred from them.

## Decisions and limits

Adopt a staged Rust backend/control migration with retained static UI and parity
fixtures. Establish owner authority before sensitive APIs, compiled OS policy
before isolation claims and separate NAS data ownership. Use in-process cache
first; optional Redis only after measured shared-cache benefit.
See ARCHITECTURE.md and SECURITY.md for contracts and REUSE.md for primary sources.

This is source inspection, not runtime verification, browser review, security
penetration testing or current energy measurement. New permissions/NAS/Storage,
Debian package support and enforcement remain unimplemented at this stage.
